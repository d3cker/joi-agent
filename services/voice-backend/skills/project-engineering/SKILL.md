# Project engineering

Use this skill for implementing or repairing a software project.

1. Read repository instructions and the smallest relevant set of source files.
2. State important assumptions and preserve unrelated user changes.
3. Make the smallest cohesive implementation that satisfies the request.
4. Add regression tests for the observed behavior, including failure paths.
5. Run targeted tests first, then the broader relevant suite.
6. Update English repository documentation when behavior or configuration
   changes.
7. Hand off the outcome, verification evidence, changed paths, and one concrete
   next step if anything remains.

All file and command operations required by this workflow must use the Open
Terminal tools described by the `open-terminal-work` skill.
